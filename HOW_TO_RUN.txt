1. WHAT THE PROJECT DOES (30-second version)
--------------------------------------------------------------------------------
Goal   : forecast Delhi's daily PM2.5 (fine-dust concentration, in micrograms per
         cubic metre) for the next day and for the next 7 days.
Data   : 4 years of hourly air quality (CAMS) and weather (ERA5), plus archived
         weather FORECASTS (ECMWF), for one grid cell in central New Delhi,
         5 Aug 2022 to 20 Oct 2026 (1,538 days).
Models : old "classical" models (Naive, ARIMA, SARIMA, Holt-Winters) versus newer
         machine-learning and deep-learning models (Ridge, Random Forest,
         XGBoost, LightGBM, Prophet, LSTM, GRU) and an ensemble of them.
Result : the newer models are clearly more accurate (numbers in section 7).
Why    : Milestone 2 used only one daily average per day. Milestone 3 adds
         intraday statistics (how the day ended), other pollutants, weather and
         weather forecasts, and tests on four seasons instead of one window.

3. RE-RUN THE WHOLE PROJECT ON YOUR COMPUTER (optional, about 6 minutes)
--------------------------------------------------------------------------------
You need: a recent Python 3 (the project was built and tested with Python 3.13) and
about 3 GB of free disk space (most of it is the PyTorch package). Internet is
needed only once, to install the packages. All data is already in the folder.

Step 1  Open a terminal (macOS: Terminal; Windows: PowerShell or Command Prompt;
        Linux: any terminal) and go to the project folder, for example:
            cd path/to/Milestone3

Step 2  Create an isolated Python environment (recommended) and activate it.
        macOS / Linux:
            python3 -m venv .venv
            source .venv/bin/activate
        Windows (PowerShell):
            py -m venv .venv
            .venv\Scripts\Activate.ps1

Step 3  Install the packages (a few minutes; PyTorch is large):
            pip install -r code/requirements.txt

Step 4  Run the full analysis:
            cd code
            python milestone3_analysis.py

        You will see progress lines with time stamps. It tunes the models,
        trains four test folds, runs the LSTM/GRU in a separate process, then
        writes tables to "results/" and figures to "results/figures/". The last line is
        "ALL DONE". Running it again is fast because stages are cached in
        "results/cache" (delete that folder to retrain from scratch).

Step 5  (optional) Rebuild the dashboard, report and slides from the new results:
            cd ..
            python code/build/build_dashboard.py
            python code/build/build_report.py
            python code/build/build_ppt.py
        Then open index.html again.

Other commands (run inside the "code" folder):
  python milestone3_analysis.py --fast      quick smoke test with smaller search
                                            (writes results_fast/, not for reporting)
  python m3_forecasts.py download ecmwf_ifs025
                                            re-download the weather-forecast archive
                                            (needs internet; the file is already in data/)

5. KEY FACTS (useful for viva questions and for an AI assistant)
--------------------------------------------------------------------------------
Target and protocol
  - Target: daily mean PM2.5, modelled on a log scale, scored in original units.
  - Two horizons: next day (h=1) and week ahead (days 1 to 7 issued every 7 days).
    This is the same protocol as Milestone 2, so results are comparable.
  - Tabular models use a "direct" strategy: one model for each horizon 1..7.
Validation
  - Four consecutive 90-day test folds (Oct 2025 to Jan 2026, Jan to Apr, Apr to
    Jul, Jul to Oct 2026). Fold 4 is exactly the Milestone 2 hold-out
    (23 Jul to 20 Oct 2026). The training window expands for each fold.
  - Hyper-parameters are tuned only on data before fold 1: no test leakage.
  - Metrics: RMSE, MAE, MAPE, R2, CPCB pollution-category accuracy; significance
    by the Diebold-Mariano test.
Inputs (79 features for tabular models)
  - PM2.5 history, rolling means, intraday statistics (last hour, evening, morning,
    max, min), PM10, NO2, CO, AQI, observed weather, calendar terms, and the
    ECMWF weather forecast for the target day.
  - ISSUE-TIME RULE: for a forecast h days ahead, only the weather forecast issued
    h days earlier is used ("previous day h" in the Open-Meteo Previous Runs API),
    so the model never sees information from the future.
  - The forecast archive starts in March 2024. Earlier training days use the actual
    weather as a stand-in; every test day uses a real archived forecast.
Models
  - Classical (no forecast inputs): Naive, ARIMA(3,0,3), SARIMA, Holt-Winters.
  - Learners: Ridge, Random Forest, XGBoost, LightGBM, Prophet (no forecast inputs),
    LSTM and GRU (5 seeds averaged).
  - Ensemble = equal-weight mean of XGBoost, LightGBM, Random Forest, LSTM, GRU
    (fixed before results were seen); it is the final model.
Important files
  - results/predictions_all_folds.csv: date, fold, horizon, actual and every model's
    prediction (original units). All reported metrics can be recomputed from it.
  - results/model_comparison_m3_holdout.csv and _rolling.csv: the main tables.

6. COMMON PROBLEMS AND FIXES
--------------------------------------------------------------------------------
* "ModuleNotFoundError: No module named ..."
    The packages are not installed in the active environment. Activate the
    environment (step 2) and run "pip install -r code/requirements.txt" again.
* The program hangs on macOS at the deep-learning step.
    PyTorch and XGBoost/LightGBM contain conflicting OpenMP libraries. The code
    already avoids this by running LSTM/GRU in a separate process
    (milestone3_dl.py is started automatically). Do not merge the two scripts.
* "pip install prophet" fails.
    Prophet needs a C++ toolchain on some systems. See the official installation
    notes at https://facebook.github.io/prophet/docs/installation.html (on Linux,
    installing the build-essential package usually fixes it).
* The dashboard shows a blank page or no charts.
    Use an up-to-date browser; open the file directly (not inside an e-mail
    preview). Charts redraw when you resize the window.
* Numbers differ slightly from the report after a re-run.
    Deep-learning results can vary slightly between machines and library versions.
    On the project machine a clean re-run reproduced all tables exactly.
* "results/cache" contains old results.
    Delete the folder "results/cache" and run the analysis again.
* No internet when running.
    Fine: everything needed is in "data/". Internet is only needed to install
    packages or to re-download the forecast archive.

7. RESULTS IN ONE TABLE (PM2.5, micrograms per cubic metre; lower RMSE is better)
--------------------------------------------------------------------------------
                                          ARIMA (Milestone 2)    Ensemble (Milestone 3)
  Next-day RMSE, M2 hold-out (90 days)         14.95                  10.53  (30% lower)
  Next-day RMSE, four seasons (360 days)       22.90                  18.36  (20% lower)
  Week-ahead RMSE, four seasons                32.66                  27.54  (16% lower)
  Week-ahead R2, four seasons                   0.27                   0.48
  Correct pollution category (next day)         57%                    67%
Removing the weather forecast from the final XGBoost model raises its week-ahead RMSE
from 30.27 to 34.03, so archived weather forecasts are what unlocked the week ahead.
Known weakness: days above 120 micrograms per cubic metre are under-predicted.

8. HONEST LIMITS
--------------------------------------------------------------------------------
  - Data are modelled grid values (CAMS / ERA5), not station readings, so extreme
    peaks are smoothed. One city, one grid cell.
  - Four 90-day test periods cover each season once.
  - One weather model (ECMWF); boundary-layer height is not archived.
  - The forecast archive is relied on as defined by its provider (Open-Meteo).

9. PUBLISH ON GITHUB AND VERCEL
--------------------------------------------------------------------------------
GitHub (the whole project, about 30 MB; caches are excluded by .gitignore)
  1. On github.com create a new EMPTY repository (do not add a README).
  2. In a terminal, from inside the Milestone3 folder:
         git init
         git add .
         git commit -m "Milestone 3: forecasting Delhi PM2.5"
         git branch -M main
         git remote add origin https://github.com/<your-username>/<repo-name>.git
         git push -u origin main
     (If you prefer to push the parent folder, that works too; then set
      "Root Directory" to Milestone3 in the Vercel project settings.)

  Suggested repository settings (on the repository page, "About" gear icon):
     Name         delhi-pm25-forecasting
     Description  Forecasting Delhi's PM2.5: ARIMA vs XGBoost, LightGBM, Prophet, LSTM,
                  GRU and an ensemble, with archived weather forecasts (CSET 369)
     Topics       time-series, forecasting, pm25, air-quality, delhi, xgboost, lstm, prophet
     Website      paste the Vercel address here once it exists
  The README is shown automatically on the repository's front page.

Vercel (publishes the website: index.html, plus the report, slides and this guide)
  1. Go to vercel.com, choose "Add New", then "Project", and import the GitHub
     repository.
  2. Leave the settings as they are: there is nothing to build, because index.html
     is at the top level of the repository. If asked, choose Framework Preset
     "Other". .vercelignore keeps code and data out of the website.
  3. Click Deploy. In under a minute you get an address like
     https://<project-name>.vercel.app that shows the dashboard. The footer links
     download the report, slides and this guide.
  Alternative from the terminal:
         npm install -g vercel
         cd Milestone3
         vercel --prod
  After re-running the analysis, refresh the website before pushing again:
         python code/build/build_dashboard.py
  Data attribution (Open-Meteo, CC BY 4.0; CAMS; ERA5; ECMWF) is already in the
  dashboard footer and in README.md; keep it if you publish.
